# TASK 0

- 网络的知识

  1. 什么是ip：IP协议定义了在路由器和端系统之间发送和接受的分组格式，是一个网络层协议，提供不可靠服务；IP地址定义了服务器的固定的、周知的地址，可以标识主机
  2. 什么是端口号：表示一台计算机中的特定进场所提供的服务；可以指定运行在接受主机上的接受套接字，用于为运输层协议提供分配套接字的依据
  3. 什么是url：统一资源定位符
     1. 方案：表示使用的协议
     2. 权威：
        1. 域或IP地址，指示web服务器
        2. 端口
     3. 资源路径
     4. 参数：用于执行额外操作
     5. 锚点：表示在资源中的定位
  4. 什么是http：超文本传输协议
     1. 定义了用户与服务器有关web页面的交互方式
     2. 使用TCP
     3. 无状态协议：不保存关于用户的任何信息
  5. http的状态码大致表示什么意思比如500、200、400等等：
     1. 1**：信息，服务器收到请求，需要请求者继续执行操作
     2. 2**：成功，操作被成功接收并处理
        1. 200：OK，请求成功，一般用于GET与POST请求
     3. 3**：重定向，需要进一步的操作以完成请求
     4. 4**：客户端错误，请求包含语法错误或无法完成请求
        1. 400：Bad Request，客户端请求的语法错误，服务器无法理解
     5. 5**：服务器错误，服务器在处理请求的过程中发生了错误
        1. 500：Not Implemented，服务器不支持请求的功能，无法完成请求

- 下面的准备有不少可以结合着apifox上写的内容来理解

  1. 接口是什么：规定了实现本接口的类或接口必须拥有的一组规则，它是抽象的使同类事务实现可替代性及通用性的手段

  2. 请求参数是什么；请求的header是什么，可以包含哪些信息；请求体有哪些格式，大概长什么样（比如json格式、form-data格式等等）；

     HTTP请求报文

     1. 请求行

        1. 方法字段
           - GET：浏览器请求对象
           - POST
           - HEAD：服务器用一个HTTP报文进行响应，但是并不返回请求对象
           - PUT：允许用户上传对象到指定的web服务器上指定的路径
           - DELETE：允许用户或应用程序删除web服务器上的对象
        2. URL字段
           - 请求对象的标识
        3. HTTP版本字段
           - 自解释

     2. 首部行（header）

        1. 指明对象所在的主机
        2. 选择持续连接或非持续连接
        3. 指明用户代理，即向服务器发送请求的浏览器的类型
        4. 选择语言

     3. 空行

     4. 实体体

        1. 使用GET方法时为空

        2. 使用POST方法时才使用，包含的是用户在表单字段中的输入值

        3. 以键值对的形式表示请求参数的数据

           1. json：

              1. application/json作为请求头，实体体部分填充序列化的json字符串

              2. 示例：

                 {"title":"test","sub":[1,2,3]}

           2. form-data:

              1. 以表单形式提交，主要用于上传文件，以；作为分隔符

              2. 示例：

                 ----WebKitFormBoundaryE19zNvXGzXaLvS5C

                 Content-Disposition:form-data;name="n1"

  3. 响应参数是什么；响应的header是什么，可以包含哪些信息；响应的格式有哪些?(json格式、binary格式)；

     HTTP响应报文

     1. 初始状态行

        1. 协议版本字段
        2. 状态码
        3. 相应状态信息

     2. 首部行(header)

        1. 发送完毕报文后是否关闭连接
        2. 指示服务器产生并发送该响应报文的时间
        3. 指示该报文是由什么服务器产生的
        4. 指示该对象创建或最后修改的时间与日期
        5. 指示被发送对象中的字节数
        6. 指示实体体中的对象类型

     3. 实体体

        1. json：

           1. 一对key：value构成json的基本元素，元素之间逗号隔开，一对{}括起来一个json对象，一对[]括起来的是一个json数组

           2. 示例：

              [
                  {
                      "id": 3,
                      "name": "绿色食品"
                  },
                  {
                      "id": 4,
                      "name": "鞋子"
                  }
              ]

        2. binary：

           1. 二进制传输数据，通常用来上传文件，由于没有键值，一次只能上传一个文件
           2. 请求体内容就是文件内容
           3. 示例：1234

           参考：[Http Body 的四种格式_请求体格式-CSDN博客](https://blog.csdn.net/oneby1314/article/details/113406924)

  4. 统一的接口是怎么做到前后端开发能够分离的？

     1.   只需要提前约定好接口文档，然后分别独立开发即可
     2.   接口可以保证前后端团队之间的协作顺畅
     3.   接口命名规范可以提高代码的可读性和维护性，减少团队成员之间的理解差异，支持前后端独立开发

  5. 我们项目采用rest风格接口，那么restful接口是怎么规范的呢？

     1.   通用URL语法：`URI = scheme "://" authority "/" path  [ " ? '' query  ][ "#" fragment]`
          1.   scheme:底层协议
          2.   port：端口
          3.   path：资源访问路径
          4.   query：发送给服务器的参数
          5.   fragment：锚点，定位到页面的资源
     2.   URL中不能有动词，动词由HTTP中的GET/POST/PUT/DELETE表示
     3.   URL中结尾不应包含斜杠“/”
     4.   正斜杠分隔符“/”必须用于指示资源之间的层次关系
     5.   使用“-”而非“_”
     6.   路径中区分大小写且首选小写字母
     7.   路径名词均为复数
     8.   使用标准HTTP状态码作为返回状态码
     9.   参考：[RESTful API规范（详细版）_restful api接口规范-CSDN博客](https://blog.csdn.net/qq_37257657/article/details/81206520)

  6. 怎么处理异常反馈给前端？

     1.   编写捕获异常的包装类，定义异常的错误码和错误信息
     2.   在抛出异常时将异常信息转换为标准HTTP响应返回给前端service层
          - service层：业务层，专注业务逻辑，数据库操作通过控制一个或多个Dao层（实现对某个表、某个实体的增删改查）实现
     3.   将详细的异常信息记录到日志中


- unix时间戳的概念

  因为我们用到了许多与时间相关的内容，存在数据库里面的时间可不能是字符串了，因为我们会有不少比较的操作，使用的是unix时间戳,[理解unix时间戳是什么，时区是什么](https://blog.mango.im/posts/timestamp-and-time-zone/#:~:text=UNIX%E6%97%B6%E9%97%B4%E6%88%B3%EF%BC%9A%E6%98%AF%E4%BB%8EUTC%E6%97%B6%E9%97%B41970%E5%B9%B41%E6%9C%881%E6%97%A5%E8%B5%B7%E5%88%B0%E7%8E%B0%E5%9C%A8%E7%9A%84%E7%A7%92%E6%95%B0%EF%BC%8C%E4%B8%8D%E8%80%83%E8%99%91%E9%97%B0%E7%A7%92%EF%BC%8C%E4%B8%80%E5%A4%A9%E6%9C%8986400%E7%A7%92%EF%BC%8C%E5%AE%83%E6%98%AF%E5%92%8C%E6%97%B6%E5%8C%BA%E6%97%A0%E5%85%B3%E7%9A%84%EF%BC%8C%E6%97%A0%E8%AE%BA%E5%9C%A8%E5%9C%B0%E7%90%83%E4%B8%8A%E7%9A%84%E9%82%A3%E4%B8%AA%E8%A7%92%E8%90%BD%EF%BC%8C%E5%90%8C%E4%B8%80%E6%97%B6%E5%88%BB%EF%BC%8CUNIX%E6%97%B6%E9%97%B4%E6%88%B3%E9%83%BD%E6%98%AF%E4%B8%80%E6%A0%B7%E7%9A%84%EF%BC%8C%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%9A%84%E6%9C%AC%E5%9C%B0%E6%97%B6%E9%97%B4%E5%B0%B1%E6%98%AF%E6%A0%B9%E6%8D%AE%20Unix%E6%97%B6%E9%97%B4%E6%88%B3,%2B%20%E6%97%B6%E5%8C%BA%E5%B7%AE%20%E8%BD%AC%E6%8D%A2%E8%80%8C%E6%9D%A5%E7%9A%84%E3%80%82)这是一篇不错的资料

  1. unix时间戳是什么：是世界协调时间（UTC）从1970年1月1日（UTC/GMT的午夜）开始所经过的秒数，不考虑闰秒；UNIX时间戳的0按照ISO 8601规范为 ：1970-01-01T00:00:00Z

  2. unix时间戳和我们平时的时间加时区的方式有什么关系；unix时间戳有时区的概念吗？平时使用UTC+时区，unix直接使用UTC；unix时间戳和时区无关，没有时区概念

  3. Java中是如何获取时间戳的：
     1. System.currentTimeMills();

     2. new Date().getTime()

     3. Calendar.getInstance().getTimeInMillis()

  4. 除了unix时间戳，我们用同样的原理处理每天的时间，比如"8:00"这样的时间，想想我们是如何利用时间戳的原理将它转换为纳秒数来表示时间的：
     1. 获取时间戳
     2. 乘以1000获得毫秒级别数值
     3. 再乘以1000获得纳秒级别数值
     4. 加上时区获得时间
